# 3D穴検出フィクスチャ

`test-models/fixtures/`には、[`supported-hole-contract.md`](supported-hole-contract.md)で定義した形状・穴端・方向の30通り、方向境界2件、径と深さの境界6件、円半径偏差・多角形辺長偏差・多角形角度偏差の境界9件、誤検出・破損メッシュ6件を収録しています。

各ASCII STLの期待属性は`manifest.json`に記録されています。内容はケースID、ファイル名、形状、軸、径または対辺寸法、深さ、穴端分類、期待結果、除外理由です。

`negative-open-groove.stl`と`negative-broken-mesh.stl`は、壊れた形状を誤採用しないことを確認する意図的な非多様体メッシュです。`manifest.json`では`printable: false`および`topology: intentionally_non_manifold`として識別し、OrcaSlicerのスライス統合検証から除外します。それ以外の51件は`closed_two_manifold`です。

## matrixフィクスチャの形状

統合検証に使う`matrix-*`の30件だけは、**外形がワールド軸に整列した直方体**で、その中を穴だけが傾いて貫きます。外形まで穴の軸で作ると、傾斜角のぶんブロックごと傾いてプレートへ線接触し、OrcaSlicerが「オブジェクトはプレートと接触していないため造形できません」と判定して造形不可になるためです。

線接触が原因であることは第1レイヤの断面寸法で確認しました。45°で`0.40×4.68mm`、60°で`0.46×5.57mm`しかなく、0°の`20.00×3.97mm`、90°の`20.00×20.00mm`とは桁が違います。作り直し後は第1レイヤの接地面が最小でも`12×20mm`あり、サポート無効のままCLIが30件すべてをスライスできました。

穴が抜ける主軸は、水平穴（0°）だけX、それ以外はZです。こうすると外形が板状になり、第1レイヤがプレートへ面で接触します。最小でも12×20mmの接地面を持ちます。穴が抜ける方向以外には、穴の壁面から8mm以上の材料を残しています。

外形が軸整列なので、傾斜穴の端面は斜めに切られます。そのぶん軸方向に測った深さは公称値より深くなるため、`manifest.json`の`depth_mm`には生成時の実測値を記録しています。検出側も穴の壁面を軸方向に測るので、両者は一致します。

matrix以外のフィクスチャは検出ロジック専用でOrcaSlicerに読み込ませないため、穴と同軸の外形のままです。

## 再生成

```bash
PYTHONPATH=src python3 tools/fixture_suite.py
```

生成は決定的で、同じ環境なら常に同じ内容になります。通常の全テストに、生成結果とコミット済みファイルの一致検証が含まれます。

ただし**STLはバイト単位では一致しません**。座標を三角関数から求めるため、最終桁がlibmとPythonのバージョンで変わります（実測で相対1e-15程度）。桁を落として吸収することもできません。検出の許容差が1e-9のためそれを下回る量子で丸める必要がある一方、丸め境界をまたぐ値が環境差によって確率的に生じるためです。

そこで一致検証は、STLの構造を完全一致、数値を相対1e-12で比較します。手による編集も生成器の変更も、この精度で検出できます。`manifest.json`は測定値を9桁へ丸めて書くため、バイト単位で比較します。

## OrcaSlicerなしの検証

```bash
PYTHONPATH=src python3 tools/run_fixture_harness.py
```

ハーネスはSTLを読み戻し、正式版の候補検出器と穴端分類器へ渡してマニフェストの期待属性と比較します。プロジェクト全体の幾何回帰テストは次の1コマンドで実行できます。

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```
